# 제품 비교와 미해당 선택: SigLIP2 / Luna Decisions

2026-10-09 본선 신규 시험. **운영 모델·PPE 판정·경보는 변경하지 않았다.**

## 결론

Decisions로 등록 사진과 비교해 '미해당'을 고르는 것은 이번 입력에서 실제 동작했다. 하지만 지금 프롬프트를 SigLIP 대신 바로 쓰거나 PPE 요청에 통합하는 것은 보류한다. 낮은 해상도의 실제 흰색 영상은 판단 불가였고, 탈의 사진은 회색 후보로 오판했다. 특히 제품 참고 사진을 PPE 요청에 합쳤을 때 실제 미착용 부위를 착용으로 바꾸는 퇴행이 나왔다.

## 고정한 방법

- 실행: 주 시험 2026-10-09 13:25:27~13:25:43 KST, RTX 3090, gpt-6-luna. 관제 실행은 시작 전 active=null이었다. 전용 격리 장비나 장기 부하 시험은 아니다.
- 기존 사전 사진과 오늘 저장한 실제 영상 crop 10개를 예측 전에 manifest로 고정했다. 사례마다 2회, 시드 20261009로 순서를 섞었다. 두 번의 같은 사진 추론은 서로 독립인 새 사례가 아니다.
- 흰색 P11 3장, 회색 P04 2장의 등록 몸통 사진을 사용했다. API에는 이름/모델명/정답/파일명 대신 R1/R2 사진만 제시한다. 카탈로그 사진 안의 로고는 가리지 않았으므로 로고/사진 편향을 배제한 시험이 아니다.
- SigLIP은 같은 query crop을 새로 임베딩하고 기존 reference embedding과 비교한다. 활성 순위는 P11/P04, 보관 P12는 등록 외 대조 점수만 산출한다. Decisions에는 활성 5장만 전송한다. 대조군 정보를 동일하게 제공하는 학술적 모델 성능 비교가 아니라 현재 검색 경로와 대안 판정의 동작 비교다.
- Decisions 제품 단독 요청은 같은 query crop 1장 + reference 5장, detail=original, JPEG 95다. SigLIP은 원래 로컬 384px padding 전처리를 쓴다. 같은 crop이지만 모델별 전처리는 다르다.
- 선택지는 R1/R2, none(보이는 차이에 의한 미해당), uncertain(증거 부족), no_coverall(관찰 몸통 미착용)이다. 제품 질문은 기존 margin 0.2 규칙, PPE는 기존 top1 규칙을 사용한다. 점수는 보정된 안전 확률이 아니다.
- PPE 비교는 실제 영상 3개 입력의 2회씩, 기존 PPE+색상 4장 요청과 여기에 query 1장/등록 5장/제품 질문을 더한 10장 요청을 교대로 호출했다. baseline과 combined는 같은 관찰/정책을 쓴다.
- 별도 탈의 실패 진단 2회는 결과를 본 뒤 추가했으므로 주 시험의 시간/사례 집계에 섞지 않았다. 전체 Luna 34회, HTTP 200 및 파싱 성공 34회. 성공 응답 수는 판정 정확도가 아니다.

공식 [Decisions 안내](https://developers.openai.com/api/docs/guides/decisions) 및 [요청 형식](https://developers.openai.com/api/reference/resources/decisions/methods/create)을 확인하고 기존 운영과 같은 endpoint/HTTP 방식/5초 timeout, 자동 재시도 없음으로 실행했다.

## 속도

이미지 파일 읽기·검출·Pose·영상 디코딩·UI 표시·관찰 대기·연속 경보 확정은 아래 시간에서 제외된다. SigLIP은 query 인코더+검색, API는 입력 인코딩+HTTP 왕복+응답 파싱이다. SigLIP reference 생성 비용은 제외된 운영상 warm 비교다.

| 방식 | 횟수 | 중앙값 | 평균 | 최소~최대 |
| --- | ---: | ---: | ---: | ---: |
| SigLIP2 검색, warm | 20 | 16.5ms | 17.1ms | 15.4~20.6ms |
| Decisions 제품 단독 | 20 | 415.5ms | 436.0ms | 331.0~694.5ms |
| 기존 PPE+색상 | 6 | 396.9ms | 403.7ms | 310.3~564.7ms |
| PPE+색상+제품 통합 | 6 | 428.3ms | 451.2ms | 412.2~509.3ms |

모델 초기 로딩 935.2ms와 첫 SigLIP 추론 297.3ms는 warm 표에서 제외했다. 제품 API 첫 요청은 694.5ms로 표에 포함했으며 로컬 모델의 cold start와 동일한 의미는 아니다.

같은 입력/회차별 통합-기존의 추가 지연은 **중앙값 56.2ms, 평균 47.5ms**, 범위 -56.6~110.6ms였다. 표의 두 중앙값 차이 31.5ms와 paired 차이 중앙값은 서로 다른 통계다. 음수 한 쌍은 네트워크/실행 변동을 보여 주며 통합이 빨라졌다는 증거가 아니다. 소수 반복으로 p95/서비스 SLA를 주장하지 않는다.

제품 단독의 인코딩 중앙값 3.9ms / HTTP 왕복 411.1ms. 기존 왕복 391.5ms, 통합 왕복 421.6ms. 서버 내부 순수 모델 시간은 측정하지 못했다. 통합 입력 토큰은 기존 대비 1,386~1,512 증가했으며 왕복이 비슷해도 입력 비용까지 같다는 뜻은 아니다. 이 호출들의 reported cached_tokens는 0이었다.

## 통합 요청에서 발견한 퇴행

주 시험 6쌍 중 V08 주 착용자 2쌍은 respirator가 기존 uncertain에서 통합 covered로 바뀌었다. 나머지 두 사례의 부위 선택은 같았다. 이는 제품 질문 추가가 PPE 답변과 완전히 독립적이지 않다는 근거다.

탈의 crop에는 검은 셔츠 외에 남은 보호복과 돕는 사람의 팔도 들어 있다. 제품 단독은 두 번 모두 R2(점수 0.59, margin 0.38), no_coverall 점수 0이었다. 사람 전체/부위 맥락을 추가한 별도 진단 결과:

| 진단 | 몸통 | 왼팔 | 제품 | 총시간 |
| --- | --- | --- | --- | ---: |
| 기존 PPE+색상 | uncovered | uncovered | 별도 질문 없음 | 652.4ms |
| PPE+색상+제품 | **covered** | **covered** | **R2** | 779.6ms |

기존 PPE가 포착한 미착용을 통합 요청이 놓쳤다. 참고 사람 혼동과 질문/맥락 간 영향 중 무엇이 원인인지 분리한 인과 시험은 아니며, 더 큰 사진을 넣으면 해결됐다고 주장할 수 없다. 이 실패를 숨기거나 미착용 기준을 낮추지 않았다.

## 적용 판단과 재현

현재 운영은 유지한다. 이후 제품 전용 Decisions를 검토할 때도 PPE와 결과를 분리하고, 미착용 우선/판단 불가 비승인/같은 대상 연속 2회 경보 원칙을 유지해야 한다. 등록 외 거부는 유망하지만 정확 제품 식별·안전 인증·화학 적합성 판단으로 승격하지 않는다. 실패 입력에만 프롬프트를 맞춰 재시험한 것을 일반 성능 향상으로 발표하지 않는다.

```bash
PYTHONPATH=. .venv/bin/python scripts/compare_product_decisions.py \
  --manifest .data/product-comparison/manifest.json \
  --output .data/product-comparison/new-run --repeats 2
```

명령은 새 유료 API 호출을 실행한다. 기존 로컬 환경의 OPENAI_API_KEY가 필요하다. 출력 폴더가 있으면 덮어쓰지 않고 종료한다. manifest는 cases(id/query/optional context/combined), product_order, references(기존 embedding와 image_path), site_products, policy를 포함한다. 시험용 snapshot은 운영 DB를 읽기 전용으로 준비했으며 스크립트는 DB에 쓰지 않는다.

Manifest SHA-256: `50e7da41f601f4e9745b7f07781567396e3e5b2804b5c3b887894019b9bda3ae`. 원본·DB·API 키·개인 crop·원응답은 공개 커밋에 포함하지 않는다. 기존 사전 자료와 예측 기록은 삭제·수정하지 않았다.

## 후속 사용자 승인과 분리 적용

위 표는 초기 reference-membership-probe-v1의 고정 비교 결과다. 이후 사용자가 Decisions 메인 사용을 승인하여 product-decisions-separated-v1을 운영에 적용했다. **참고 사진을 PPE 질문과 같은 요청에 섞는 방식은 채택하지 않았다.** PPE를 먼저 적용하고 제품은 별도 작업자에서 호출하며, 몸통 미착용/판독 불가는 제품 호출을 생략한다. SigLIP은 보조 표시에만 남았다. 새 실제 확인(제품 평균 약 0.41초), 유사 흰색 판단 불가 및 채택의 한계는 DEVELOPMENT_LOG.md의 'OpenAI 우선: Decisions 제품 메인 적용' 절에 별도로 기록한다. 초기 시험과 다른 입력/프롬프트의 결과를 한 정확도 표로 섞지 않는다.

## 최신 기준: 색상 표준화와 호출 방식 비교

사용자는 비슷한 흰색 제품을 구분할 필요 없이 현장 색상별 대표로 표준화한다고 정했다. 따라서 최신 product-decisions-site-standard-v2는 같은 흰색/보호복 형태를 P11 등록 표준으로 분류한다. 기존 v1 표의 exact-family 목표와 혼합하지 않는다. 지정한 이전 세션의 PPE 프롬프트(top1, 전면형 방독면, 보이는 부위, 후드/외관상 여밈)는 그대로 유지했다.

2026-10-09 동일 사진 4조건, 각 방식 1회, 새 HTTP 요청 20회(오류 0)의 제한된 개발 비교:

| 방식 | 두 결과 완료 중앙값 | 범위 | 전체 입력 토큰 |
|---|---:|---:|---:|
| 순차 별도 요청 | 942.4ms | 742.7~1682.6ms | 24,768 |
| 병렬 별도 요청 | 586.2ms | 387.3~916.2ms | 24,768 |
| 한 요청 통합 | 583.5ms | 408.7~774.2ms | 21,386 |

토큰은 4조건 합계다. 순차도 두 질문을 모두 호출해 작업량을 맞췄다. 모든 지연은 네트워크/인코딩 포함이며 검출부터 경보까지의 지연이 아니다. PPE 결과만의 중앙값은 순차 472.9ms/병렬 586.2ms이므로 병렬이 모든 개별 호출을 가속한다고 해석하지 않는다.

- 흰 Tyvek 측면과 V08은 세 방식 모두 흰 등록 표준 후보. 색상 표준 분류이지 실제 제품 정답 확인이 아니다.
- 노란 AlphaTec은 순차/병렬 none, 통합 uncertain. V08 방독면은 독립 요청 uncertain, 통합 covered. 어느 판정이 정답인지 이 비교만으로 확정하지 않는다.
- 검은 셔츠는 세 방식 모두 PPE torso uncovered지만 제품 원응답은 회색 P04로 잘못 분류했다. 독립 PPE gate를 적용해야 제품 후보를 제외할 수 있다.

**채택은 독립 병렬 요청**이다. 통합은 이 표본에서 입력 토큰 13.7% 절약, 지연은 병렬과 비슷했지만 PPE 질문에 참고 사진을 넣는 영향이 남는다. 제품 결과는 정확히 같은 부모 PPE 결과와 결합하고 미착용/불확실이면 사용하지 않는다. 이미 선행 호출된 제품 비용은 발생할 수 있다. 새 실제 두 영상의 API 중첩·미해당 HIGH 검증과 잔여 한계는 DEVELOPMENT_LOG.md 마지막 절에 기록했다. 재현 코드는 scripts/compare_decision_routing.py, 원본/원응답은 Git 제외 경로에만 보관한다.
