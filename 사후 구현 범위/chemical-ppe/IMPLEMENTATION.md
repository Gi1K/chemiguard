## 후속 변경: 홈페이지 제품 DB와 매일 신규 보호구 확인 (2026-10-09)

- 근거/사용자 확정: 기존 홈페이지는 44개 제품·150개 출처의 고정 JSON을 읽었고 정기 신제품 발견 기능이 없었다. 사용자는 홈페이지 관리 차원의 자동 수집·DB 반영을 요청했으며 연결 대상은 홈페이지 DB부터, 주기는 한국 시간 매일 오전 9시로 확정했다. CCTV 관제 DB·착용 정책은 별도다.
- 변경: `catalog_store.py`에 기존 데이터의 최초 이관, 제조사·정확 모델의 중복 방지, 변경 버전·출처 해시·실행 이력을 가진 SQLite 저장소를 추가했다. 원본 8개는 그대로 보존한다. 공식 제조사 8곳의 허용 도메인과 순환 점검 목록을 구성하고, `catalog_sources.py`가 제한된 HTML을 읽어 모델·제품명·품목 문구가 함께 존재하는지 확인한다. `catalog_admin.py`는 로컬 입력만 받아 원자적으로 반영한다. 외부 쓰기 API, 출처 차단 우회, 사진 수집은 추가하지 않았다.
- 홈페이지 연결: 제품 목록·상세·비교·선택 목록은 DB를 읽고 활성 화면에서 60초마다 변경을 확인한다. 상담 요청도 동일 DB의 스냅샷으로 계약과 출력 ID를 생성한다. 자료 링크는 최신 API를 열며, 서버 연결 실패 때는 기본 정적 자료와 명확한 상태를 표시한다. `제품 자동 업데이트`에 등록 일정·최근 실행·추가/갱신·실패 출처를 표시한다. 수집마다 빌드나 재시작할 필요가 없다.
- 반영 경계: 신규 제품은 제조사 기본 정보만 확인하며 최초 발견과 출시일을 구분한다. 성능·인증·재고·사진 권한을 추정하지 않는다. `recommendation_eligible=false`인 신규 제품은 자동 후보·조합 출력 스키마에서 제외한다. 수동 비교·검토 초안은 가능하나 사용 승인으로 바꾸지 않는다. 기존 제품의 성능·인증을 자동 덮어쓰거나 제품을 삭제하지 않는다.
- 실제 첫 수집: DuPont 공식 SafeSPEC 및 QS127T GR 제품 페이지를 확인하고 기존 DB에 없던 `DuPont™ Tychem® 2000 SFR · QS127T GR`을 추가했다. 운영 목록 44→45개, 출처 150→151개. 출시일은 미확인이다. Ansell 페이지의 HTTP 403은 실패로 남겨 실행 상태가 부분 성공이며 전체 성공으로 표시하지 않았다. 실제 입력·DB·스크린샷은 Git 제외 `.runtime`에만 둔다.

- 실제 확인: 필요한 오프라인 제품 DB 검사(영속화·중복·가짜 제품명 거부·부분 실패·원본 불변·미검토 제품 추천 차단·공개 API 경로 정제), 기존 API 계약/SDK 검사, 사진 입력 검사 통과. 빌드의 사전 SHA256 8개 일치·정적 기본 제품 44개·공개 원본 사진 0개, JavaScript 구문 및 diff 공백 검사 통과. 브라우저에서 운영 제품 45개/출처 151개, 신규 모델 검색·상세·검토 전 표시·관리 패널·최신 자료 링크를 확인했고 콘솔 오류 0개였다. 이번 제품 관리 작업의 유료 상담 API 호출은 0회다.

## 후속 변경: 초보자 상담과 라벨 사진 입력 (2026-10-09)

- 근거: 직전 초보자 3턴 점검에서 한 질문에 여러 조건이 묶였고, 실제 첨부 기능 없이 라벨 사진을 요구했다. 사용자는 이를 개선하고 사진 질의와 초보자도 따라갈 수 있는 흐름을 요청했다. 기존 점검 결과를 재생하지 않고 새 구현에서 실제 대화를 수행했다.
- 변경: 홈에 `처음이라면 상담부터`, 상담에 `처음이라 잘 모르겠어요` 시작 버튼을 배치했다. 전문 예시는 쉬운 시작 문장으로 바꾸고 상세 선정 기준은 접어 두었다. 별도 `counseling_policy.py`에서 질문을 한 번에 하나로 제한하고, 모르면 사진 가능 여부를 묻고 사진이 없으면 글자 입력·담당자 요청 문장을 안내하도록 했다. 질문 배열 스키마도 최대 1개로 제한했다. 모델이 하나의 문장에 여러 요구를 묶는지에 대한 의미 검증은 프롬프트와 실제 사례 점검이며 완전한 자동 보장은 아니다.
- 사진 흐름: 최대 2장 선택 → 미리보기/제거 → 명시적으로 보내기 → Luna가 라벨 글자 판독 → 사용자가 수정·확인 → 기존 물질 조회/상담 순서다. 글 없는 사진 요청도 가능하다. 확인 전에는 추천·제조사 조회를 하지 않고 판독 텍스트를 상담 이력에서 제외한다. 잘못된 형식, 원격 URL, 과다 크기/개수, 만료된 확인 요청은 유료 호출 전에 거부한다. 사진 원본은 저장하지 않고 메타데이터를 제거해 메모리에서 전달한다. 처리 중·이전 판독의 중복 확인 버튼도 차단한다.
- 실제 확인: Agents API + `gpt-6-luna`로 새 UI에서 3턴을 수행했다. (1) 초보자 시작 문장에 사진 가능 여부를 한 가지 질문으로 안내, (2) 직접 만든 가상 영문 라벨을 글 없이 첨부해 제품명·제조사·성분 미표기 등을 실제 이미지 입력으로 판독, (3) 판독 텍스트를 수정해 확인하자 수정한 내용과 가상 라벨임을 반영하고 현장 관리자/구매 담당자에게 안전보건자료를 요청하는 다음 질문을 제시했다. 3개 응답·질문 3개, 후보/조합 0개, UI 오류 0개, 사진 미리보기 로드 성공, 재확인 버튼 비활성화를 확인했다. 정상 상담 2회(각 2세션) + 사진 판독 1회(1세션), 총 5개 Agents 세션이며 완료 후 미정리 세션은 0개였다. 실제 청구 금액은 측정하지 않았다.
- 이 실제 응답에서 아직 알려주지 않은 제품을 세척제로 부르거나 CAS 같은 용어를 불필요하게 언급한 부분이 있어, 제품 종류를 단정하지 않고 현재 할 일만 쉬운 말로 설명하도록 마지막 문구를 보완했다. 이 문구 보완 뒤 유료 반복 호출은 하지 않았다. 사진을 통한 실제 현장 성분·보호구 적합성 검증은 수행하지 않았다.
- 필요한 검사: 빌드의 사전 SHA256 8개 일치, 제품 44개·공개 사진 0개. 기존 API 계약 검사와 실제 SDK 이미지 입력 직렬화/세션 종료 검사 통과. 새 사진 흐름 검사에서 실제 이미지 형식·메타데이터 제거·수정한 텍스트만 전달·확인 전 추천 방지·읽기 어려운 사진 처리 확인. 브라우저 콘솔 오류 0개. 390×844 화면에서 사진 선택·미리보기·제거 성공, 문서 폭/스크롤 폭 375/375px로 가로 넘침 없음. 기본 화면 크기로 복원했다.
- 실행 반영: 사용자 `chemiguard-catalog.service` 재시작으로 새 Python 코드와 정적 빌드를 적용했다. 원격 접속·키·호스트·기존 서비스와 일일 예산 설정은 변경하지 않았다. 사진 입력도 기존 시연 코드와 Origin 검사를 거친다. 대화는 여전히 6회/2시간 제한이며 사진 판독·확인도 각각 1회 요청이다. 실제 검증 기록과 자체 생성 라벨은 Git 제외 `.runtime/novice-photos-20261009`에만 보관했다.
- 범위: 새 코드·검사·문서·의존성 Pillow는 모두 `사후 구현 범위/chemical-ppe`에만 둔다. 사전 원본, 사용자 변경, 영상 감시 앱과 Medium/Large·Luna Decisions는 변경하지 않는다. 사진 입력은 기존 제품 사진 44개의 재배포 권한이나 공개 배포 상태를 바꾸지 않는다.

## 후속 변경: Agents API 연결

2026-10-09 사용자가 키를 입력하고 Agents API 사용 및 Sol·Luna 연결 확인을 요청했다. 기본 연결을 `PPE_BACKEND=agents`, `OPENAI_MODEL=gpt-6-luna`로 변경했다. 원래 사전 지침·제품·출처 검증 및 CAS → 제조사 조회 → 조합 순서는 유지했다. 기존 Responses 경로도 명시적으로 선택할 수 있다.

- Sol(`gpt-6-sol`)·Luna(`gpt-6-luna`) 모두 모델 접근 200 및 Agents API의 실제 구조화 응답을 확인했다. 연결 확인용 세션은 각각 종료 후 삭제했다.
- Luna로 황산 30%·20°C 이송이라는 가상의 검증 사례 1건을 실행했다. 약 51.1초에 제조사 3종 조회, 검토용 부분 조합 2개, 추가 질문 2개를 반환했다. `approved=false`, 미정리 외부 세션 0개였다. 이는 연동 동작 확인이며 선정 품질 전체 검증이나 현장 승인이 아니다.
- 실제 완료한 Agents 세션은 연결 확인 2개 + 상담의 계획/최종 단계 2개다. 비용 설정이 거절된 초기 요청에서는 답변이 생성되지 않았다. 실제 청구 금액은 측정하지 않았다.
- 현재 계정은 세션 예산 필드에 `Session budget configuration is not enabled`를 반환했다. 따라서 `PPE_AGENT_BUDGET_ENABLED=false`로 명시하고, 요청·동시성·시간·예상 토큰 예약 제한을 사용한다. 금액 상한이나 Agents 출력 토큰 상한을 적용했다고 표시하지 않는다. 예산 기능 활성화 시에만 세션별 금액 제한을 선택할 수 있다.
- 세션은 sandbox·도구·하위 에이전트 없이 실행한다. 완료된 최종 답변만 받으며, 종료 시 세션 삭제를 요청한다. 실패·시간 초과 시 취소 후 삭제한다. 정리 전 ID만 로컬에 보관하고 재시작 후 다음 요청에서 처리한다. 삭제 실패 시 새 세션 생성을 중단한다.
- 오프라인 검사에 실제 OpenAI SDK의 SSE 파싱·초기 idle 무시·미완료 스트림 거부·취소/삭제 확인만 추가했다. 키·시연 코드·실제 응답 기록은 Git에 포함하지 않는다.

아래 표와 검증 기록은 최초 홈페이지 구현 시점의 상태다. 현재 H02의 실제 모델 연결 확인은 위 기록으로 갱신되며, 공개 HTTPS 배포와 공개 환경 검증은 아직 남아 있다.

## 기존 성과와 이번 변경

사전 페이지의 44개 제품·150개 출처·43개 국내 구매/견적 경로, 검색·필터, 수동 조합, 작업/형식별 색상 구분, 초안 저장·복원·JSON, 상담 지침/스키마, DuPont 3종의 CAS 조회를 재사용했다. 사전 원본 8개 파일은 그대로 보존했다. 기존 상담 서버의 CodexClient는 실행하지 않는다.

이번 화면은 사용자가 사진과 모델명을 먼저 보고, 상세 정보를 필요할 때 열도록 다시 구성했다. 사진 카드 → 상세·확대 → 최대 3개 비교 → 내 조합 순서로 사용할 수 있다. 제품군 대표사진과 모델 연결 사진, 등록된 실제 색상, 구매 경로와 미확인 사항을 구분한다. 사진은 자르거나 변색하지 않는다. 모바일에서는 필터·제품 카드·상세 창을 화면 폭에 맞춰 배치한다.

기존 단일 스크립트를 역할별로 분리했다. `core.js`는 기존 공통/근거 함수, `drafts.js`는 기존 조합·초안, `bootstrap.js`는 기존 초기화의 수정본이다. `catalog.js`는 새 제품 탐색 화면, `counselor.js`는 새 Responses 연결이다. 파생 코드는 사후 폴더에 두고 파일 머리에 재사용 출처를 명시했다.

서버는 Responses로 CAS 계획과 최종 상담을 요청하고 그 사이에 기존 제조사 조회를 실행한다. 등록 제품·출처 검증, 최대 3개 조합, 추가 질문, 시험 조건·원문 행, 실패 상태를 전달한다. 키·시연 코드, 호출/예약 토큰 제한, 중지 파일, 임시 대화를 별도 Python 서버에서 관리한다.
